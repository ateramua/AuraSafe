04 / Documentation route

Browser Companion

Deep link ready

Overview

The browser extension is not stored as extensions/manifest.json in source. You generate loadable extension folders with an npm build, then load them in Chrome, Edge, or Firefox.

Prerequisite

Run the AuraSafe desktop app and unlock your vault before testing autofill. The extension talks to the desktop app over a local bridge.

Step 1 — Generate loadable extension files

From the AuraSafe project root, run the extension platform build. This copies shared extension code and writes a browser-ready manifest.json into the release folder.

cd "/Users/abditeramu/Documents/repos/aurasafe-repo/AuraSafe"
npm run extension:platform:build

Expected outputs:

  • release/extensions/chromium-platform/manifest.json — for Chrome, Edge, Brave, and Arc
  • release/extensions/firefox-platform/manifest.json — for Firefox

If those files are missing, the build did not complete. Re-run the command and check the terminal for errors.

Step 2 — Load in Google Chrome

  1. Open chrome://extensions
  2. Turn on Developer mode (top right)
  3. Click Load unpacked
  4. Select the folder release/extensions/chromium-platform (the folder that contains manifest.json, not a parent folder)
  5. Confirm the AuraSafe extension appears in the list and is enabled

Step 3 — Load in Microsoft Edge

  1. Open edge://extensions
  2. Turn on Developer mode (left sidebar or toolbar)
  3. Click Load unpacked
  4. Select the same folder: release/extensions/chromium-platform
  5. Confirm the extension is enabled

Chrome and Edge use the same Chromium build output.

Step 4 — Load in Mozilla Firefox

  1. Open about:debugging#/runtime/this-firefox
  2. Click Load Temporary Add-on…
  3. Select release/extensions/firefox-platform/manifest.json
  4. Confirm AuraSafe appears under Temporary Extensions

Firefox loads the manifest file directly. The add-on is temporary and removed when Firefox restarts unless you install a signed build later.

Step 5 — Verify the connection

  • Open the extension popup and confirm it can reach the desktop app
  • If status shows disconnected, ensure AuraSafe is running from Applications or npm run dev
  • Re-open the extension options page if you changed desktop app state
Smart tip

After changing extension source files, run npm run extension:platform:build again, then click Reload on the extension card in Chrome/Edge or reload the temporary add-on in Firefox.

07 / Developer guide

Repository & platforms

Monorepo on main

One repository, two apps (not two permanent branches)

After the mobile work merged into main, desktop and Android both live in the same GitHub repo on the same default branch. You do not maintain a long-lived “desktop branch” and “mobile branch.”

  • Desktop — electron/ + src/ at the repo root
  • Android — apps/mobile/android-app/
  • Shared logic — packages/ and services/

Use short-lived feature branches (for example fix/desktop-export or feat/mobile-vault-ui), merge back to main, then delete the branch. The old feature/mobile-android-monorepo branch can be deleted after merge.

Which folder is which?

AuraSafe/
├── DESKTOP ONLY
│   ├── electron/          Main process, IPC, crypto, backups, bridge
│   ├── src/               Next.js UI (pages, components, vault)
│   ├── scripts/           Electron helpers
│   └── extensions/platform/   Browser extension source
│
├── MOBILE ONLY (Android)
│   └── apps/mobile/android-app/
│       ├── app/           Screens (Expo Router)
│       ├── src/           Mobile providers and platform code
│       └── android/       Gradle / native Android project
│
├── SHARED (may affect both apps — test both)
│   ├── packages/        core, domain, backup, design-system, …
│   └── services/        cloud-sync, ai-orchestration, …
│
└── apps/desktop/        Thin wrapper; real desktop code stays at root

Desktop-only change

  1. Stay on main (or a short fix/desktop-… branch).
  2. Edit only electron/, src/, or extension paths — not apps/mobile/.
  3. Test: npm run dev (use the Electron window, not only the browser tab).
  4. Commit; PR title can start with desktop:.

Examples: src/components/BackupSettings.jsx, electron/main/index.mjs

Mobile-only change

  1. Stay on main (or a short feat/mobile-… branch).
  2. Edit only apps/mobile/android-app/.
  3. If you changed packages/*, run npx pnpm run build:packages first.
  4. Test: npx pnpm run dev:mobile (Expo Go) or build a release APK (below).
  5. Commit; PR title can start with mobile:.

Shared package change

Edits under packages/ or services/ can affect both desktop and mobile (vault crypto, backup format, types). After changing shared code:

npx pnpm install
npx pnpm run build:packages
npm run dev
npx pnpm run dev:mobile

Before commit, run git status: only packages/ means shared; only src/ or electron/ means desktop-only; only apps/mobile/ means mobile-only.

After pulling merged changes on your Mac

cd "/Users/abditeramu/Documents/repos/aurasafe-repo/AuraSafe"
git checkout main
git pull origin main
npx pnpm install

Desktop day-to-day: npm run dev. Mobile day-to-day: npx pnpm run build:packages then npx pnpm run dev:mobile.

Build and install the Android release APK

Use the standalone app (app-release.apk), not Expo Go, for daily use on a phone. The debug APK expects a Metro dev server.

cd "/Users/abditeramu/Documents/repos/aurasafe-repo/AuraSafe/apps/mobile/android-app/android"
export NODE_ENV=production
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
export ANDROID_HOME="$HOME/Documents/Android/sdk"
./gradlew assembleRelease

APK path: apps/mobile/android-app/android/app/build/outputs/apk/release/app-release.apk

  1. Copy the APK to your phone (USB, AirDrop, Drive, etc.).
  2. Install it; allow Install unknown apps if Android prompts you.
  3. Restore your vault from a .aura backup — data from Expo Go does not transfer into the standalone APK.
Export on desktop first

On the Mac app: Settings → backup export → save .aura → copy to the phone → open the Android app → Restore from .aura backup.
